# Android development and recorder verification

The recorder is a local Kotlin Expo module. It requires a native Android build; Expo Go and a JavaScript export cannot exercise the service. Keep native source in `client/modules/recorder/` and app configuration in `client/app.json`. `client/android/` is generated by Expo and is git-ignored. Native source changes require rebuilding the application. See the [Expo local-module workflow](https://docs.expo.dev/modules/get-started/).

Use Node 24 and npm 11 as pinned in `client/package.json`. The committed Expo 57.0.24 / React Native 0.86.3 packages select the following native tools:

These selections come from the installed Expo `template.tgz`, React Native `gradle/libs.versions.toml`, and `@react-native/gradle-plugin` build files. Recheck these files after an Expo upgrade. Android's [AGP 8.12 compatibility table](https://developer.android.com/build/releases/agp-8-12-0-release-notes) requires at least JDK 17. The [Gradle compatibility table](https://docs.gradle.org/current/userguide/compatibility.html) permits Java 21 to run Gradle 8.5 and later. Running Gradle on JBR 21 does not remove React Native's separate Java 17 compilation-toolchain requirement.

The SDK is currently under `%LOCALAPPDATA%/Android/Sdk`; Android Studio's JBR is under `%ProgramFiles%/Android/Android Studio/jbr`. `scripts/android-env.ps1` discovers these, or uses `JAVA_HOME` / `ANDROID_HOME` / `ANDROID_SDK_ROOT`. Explicit `-JavaHome` and `-SdkRoot` overrides are supported. The script sets process environment variables only for the command and restores them afterward. It does not install tools, change saved environment variables, or accept licenses.

From `client/` in PowerShell:

```powershell
./scripts/android-env.ps1
./scripts/android-env.ps1 -Command npx.cmd -CommandArguments @('expo', 'prebuild', '--platform', 'android', '--no-install')
./scripts/android-env.ps1 -WorkingDirectory android -Command ./gradlew.bat -CommandArguments @('--version')
./scripts/android-env.ps1 -WorkingDirectory android -Command ./gradlew.bat -CommandArguments @(':notes-recorder:compileDebugKotlin', ':notes-recorder:testDebugUnitTest', '--console=plain')
./scripts/android-env.ps1 -WorkingDirectory android -Command ./gradlew.bat -CommandArguments @(':app:assembleDebug', '--stacktrace', '-PreactNativeArchitectures=arm64-v8a')
```

Use the wrapper, not a system-wide Gradle installation. The first build downloads Gradle and Maven dependencies. React Native's included build configures the Foojay toolchain resolver, which may also download JDK 17 into the Gradle user cache. If policy requires an offline build, install an approved JDK 17 first and pass its directory using `-JavaHome`. Missing SDK components may be provisioned by the Android Gradle plugin only when the corresponding license was previously accepted. If a build reports a missing license, review it interactively in Android Studio's SDK Manager before continuing; do not script license acceptance.

Pass `-GradleUserHome 'F:/NotesAppBuildCache/gradle'` on this workstation to keep downloaded build dependencies on the larger F: drive. This is an optional local cache path, not a project requirement or global environment change.

To install and run on an attached phone after its USB-debugging prompt is accepted:

```powershell
./scripts/android-env.ps1 -Command adb.exe -CommandArguments @('devices', '-l')
./scripts/android-env.ps1 -Command npx.cmd -CommandArguments @('expo', 'run:android', '--device')
```

An APK assembly is a build check, not proof of recorder reliability. Keep debug APKs, recordings and raw device logs out of Git. Recordings and logs from real lectures belong under the ignored `private/` directory.

## S23 Ultra release checklist

Run with synthetic spoken audio, and record the app commit, Android/One UI version, battery settings, result and evidence for every row. Test the installed development build first, then repeat the reliability cases on the intended release build. Do not mark M2 complete until the physical-device cases pass.

| Check | Procedure and required observation | Status |
| --- | --- | --- |
| Permissions | Deny microphone access once; starting must show a useful error. Grant it and start from the visible app. Deny notifications separately; the app must explain the effect on notification controls. | Pending device |
| Basic capture | Record over two chunk boundaries; add bookmarks, pause/resume, then Stop. Play the joined file and compare its duration and bookmark timing with active recording time. | Pending device |
| Screen off | Record ten minutes with the screen off. Reopen and stop; all expected audio must play. | Pending device |
| Swipe-away | Start recording, remove the app from recents, wait over a minute, reopen. The recording must continue with a usable notification and valid audio. | Pending device |
| UI process crash | Kill only the main UI process while recording, leaving the `:recorder` process alive. Reopen and verify continuous audio and correct status. Do not use package force-stop for this test: it terminates the recorder too. | Pending device |
| Notification actions | With the screen locked, Bookmark, Pause/Resume and Stop must perform the intended action and update state on reopening the app. | Pending device |
| Phone call | Answer a call during recording, finish the call and inspect the recording. Verify a visible interruption and the implemented resume behavior; no call audio should be captured. Repeat with microphone contention from another app. | Pending device |
| Recorder process death | Stop only the recorder process between chunk commits. Relaunch the app and recover the saved chunks. Measure any loss against the 30-second target and verify the recovered file plays. | Pending device |
| Reboot | Reboot during recording, unlock and reopen the app. Recovery must offer the saved audio without silently restarting the microphone; compare the playable duration with committed chunks. | Pending device |
| Storage pressure | On a test device with deliberately limited free space, verify advance warning, graceful stopping and preservation of already saved chunks. Do not fill a daily-use phone without a backup. | Pending device |
| Battery warning | Verify low-battery indication and that committed audio remains recoverable if recording ends unexpectedly. | Pending device |
| Battery measurement | Measure an unplugged one-hour recording with screen off. Record start/end battery percent, OS settings, duration and thermal state; compare with an idle control period. | Pending device |
| Samsung battery settings | Record the actual app battery setting and sleeping-app status. Test the intended recommended setting and document any failure under the default setting. | Pending device |
| Repeated starts and recovery | Start/stop repeatedly and reopen after each interruption. There must be no duplicate sessions, empty entries, stale active state or deletion of recoverable chunks. | Pending device |

Microphone foreground services have launch and permission restrictions, including changes across Android versions. Start recording from a visible user action, and test the target Android release using the current [foreground-service troubleshooting guide](https://developer.android.com/develop/background-work/services/fgs/troubleshooting). Successful emulation cannot replace the Samsung battery, call, lock-screen and process-lifecycle checks above.
