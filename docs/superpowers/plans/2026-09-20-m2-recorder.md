# M2: Android recorder implementation

The user requested continuing after approving the M1 foundation. M1's remote release work remains pending; it is not a prerequisite for this authorized local implementation. No remote publish, merge or microphone recording is performed automatically.

## Architecture

An Android-only local Expo module lives in `client/modules/recorder`. A microphone foreground service in the `:recorder` process owns capture and storage. The Expo bridge uses Messenger IPC with correlated requests and timeouts; it never shares recorder objects or mutable in-memory session state across processes. Binding for a status read does not start the microphone. A visible-screen start first prepares the foreground service, then starts capture via an acknowledged command. No boot receiver starts the microphone.

Continuous PCM capture feeds a single AAC encoder. Complete ADTS frames rotate between approximately 30-second chunk files without restarting the microphone or encoder. Chunks are flushed to disk, then joined to an M4A file on stop. The join is verified before source chunks can be removed. Atomic journals preserve session metadata, bookmarks and interruptions. Explicit recovery runs after reconnecting and never rewrites a live session.

Initial audio settings: mono AAC-LC, 32 kHz, 32 kbit/s, VOICE_RECOGNITION source. These are provisional until spike S5 compares real lecture quality.

## Work packages

1. Toolchain: discover JDK and Android SDK; add a portable process-scoped build wrapper and device checklist. Install missing build dependencies using existing accepted licenses. Do not alter global environment variables.
2. Audio engine: capture/encode, durable ADTS rotation and validation, verified M4A join. Unit-test framing and truncated recovery.
3. Service/storage: serial command processing, atomic manifests, pause/resume, microphone-silencing gaps, bookmarks, foreground notification actions, storage/battery checks and recovery. Test storage invariants independently of Android hardware.
4. Expo bridge and app: timeout-safe IPC, Android permissions, explicit recorder controls, status/level polling with cleanup, saved/recovered recordings, and an honest unsupported state on web/Expo Go. Keep timetable domain pure.
5. Verification: existing domain suite, added native tests, strict types/lint, autolinking, Android Kotlin compilation/APK where toolchain permits, web and Android JS export, and browser regression.

## Implementation checkpoint — 2026-09-22

- Local Expo module, native service, continuous AAC chunk writer, verified join, atomic journal and recovery code are present.
- Recorder controls open from the timetable with a generated class title. Permissions/preflight warnings, pause/resume, bookmarks, stop/save, level display and explicit recovery controls are wired to the native bridge. Web/Expo Go show an unavailable state.
- The bridge cleans up failed bindings and disconnected requests. A capture ownership guard prevents a timed-out encoder from releasing its files to a new session or recovery. Polling follows screen focus and app activity; navigation returns to the existing timetable.
- Type checking, lint, 95 Jest tests, Expo dependency compatibility, static web export, Android Hermes export and desktop/mobile browser regression pass. Domain line coverage remains 98.24%.
- CI includes a separate Android compile/JVM-test job. Hosted CI has not run. Local native compilation and JVM tests still need a successful completed run before this checkpoint can claim native validation.
- Public-file privacy scan passes. No microphone was opened by the automated checks. ADB currently reports no connected phone.

## Release gates (still pending)

Code and simulator/build checks do not prove real-device reliability. M2 remains in progress until the S23 Ultra checklist in `docs/android-development.md` passes: screen-off capture, swipe-away, UI process kill, phone call, reboot recovery, storage pressure, audio continuity, and battery measurement. No phone was connected when implementation began.
